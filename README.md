# 外部笔记注入 · astrbot_plugin_note_inject

> 把本地文本文件按轮拼进系统提示词——让「会变的东西」每轮都看得见。

![外部笔记注入](logo.png)

## 它解决什么问题

AstrBot 的人设（Persona）是一段**静态**文本。但实际用起来，总有一些内容需要
「每轮都让它看见，却又**不该写死人设**」：

- 它自己随手记下的便签：谁是谁、说好要做什么、昨天答应的事
- 它给自己写的**补充人设页**：用着用着长出来的偏好和习惯
- 一份临时的**行为守则**：这周别在群里提某个话题
- 当天的**任务清单**、项目约定、共享事实
- 多角色 / 多机器之间要**共用的一小份状态**

这些内容放在普通文本文件里最顺手（能直接用编辑器改、能被别的程序写），
本插件负责在每次请求前把它们读出来，拼到系统提示词末尾。

## 效果示例

`C:\notes\memo.md`

```markdown
- 2026-11-07 22:09｜王子明天要交高数作业，记得提醒他
- 2026-11-08 10:30｜他喜欢先喝汤再吃饭
```

注入之后，模型在**每一轮**都能看到：

```
【你记着的事】
- 2026-11-07 22:09｜王子明天要交高数作业，记得提醒他
- 2026-11-08 10:30｜他喜欢先喝汤再吃饭
```

于是它可以被问「你记得我明天要交什么吗」而答得上来——**不需要**任何记忆插件、
不需要向量库、不需要工具调用。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `sources` | `[]` | 笔记来源列表，每行一个 |
| `position` | `system_prompt` | 注入到系统提示词，或作为本轮用户消息的附加内容 |
| `max_total_chars` | `1600` | 所有来源合计的字数上限 |
| `show_when_empty` | `false` | 没内容时是否也注入一句「暂无记录」（便于测试） |

### sources 写法

```
标签|文件路径|保留条数|字数上限|head或tail
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标签 | ✅ | 注入时的标题，会渲染成 `【标签】` |
| 路径 | ✅ | 绝对路径最稳；也可写相对路径 |
| 保留条数 | ❌ | 默认 8；`0` 表示不按条数限制 |
| 字数上限 | ❌ | 默认 700；`0` 表示不限制 |
| head / tail | ❌ | 默认 `tail`：取文件**末尾最新**的几条；`head` 则从头取 |

例子：

```
你记着的事|C:\notes\memo.md|8|700|tail
我自己写的补充|C:\notes\self.md|20|600|head
```

只写 `标签|路径` 也可以，其余用默认值。

## 文件格式

- 以 `- `、`* `、`• ` 开头的行算一条；
- 如果文件里**没有**这种行，则每个非空行算一条（以 `#` 开头的标题行会被忽略）；
- 编码按 UTF-8 读取，读不动时用 `errors="replace"` 兜底，不会因为一个坏字节整段消失。

## 性能

- 按 `(路径, mtime, size)` 缓存解析结果，文件没改就不重复读盘、不重复解析；
- 若某个块的内容已经出现在系统提示词里（例如人设里写过了），会跳过，不重复占用上下文；
- 单来源超限时按条截断，总预算超限时按来源顺序截断，保证不会把上下文撑爆。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/笔记注入` | 预览当前会注入的完整内容与总字数 |

## 常见问题

**Q：为什么不用记忆插件？**
A：两者解决的不是同一件事。记忆插件负责「从聊天里提炼」，本插件负责
「把一份已经整理好的文本每轮放回去」。文件小、可控、可手改、可被别的程序写入，
这是它的优势。

**Q：会不会让每轮 token 变多？**
A：会，注入多少就占多少。默认上限 1600 字，大约 1.2k token/轮。
只想让它在特定情况出现的话，把 `max_total_chars` 调小或减少来源即可。

**Q：能写文件吗？**
A：不能。本插件只读。写入交给别的东西（编辑器、其它插件、你自己的脚本）。

**Q：文件不存在会怎样？**
A：跳过该来源，不报错，其余来源照常注入。
